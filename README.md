# dmqtl

[![tests](https://github.com/BFGBgroup/dmqtl/actions/workflows/tests.yml/badge.svg)](https://github.com/BFGBgroup/dmqtl/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

`dmqtl` is a Dirichlet-Multinomial GLM score test for **composition
QTL mapping** — testing whether genetic variants are associated with
how a fixed total (e.g. gene expression, read counts) is *split*
across several categories for a given gene, such as alternative
polyadenylation site (PAS) usage, exon usage, or isoform ratios.


## Method summary

For each gene with *K* categories (e.g. *K* PAS sites) and *n*
individuals:

1. **Null model**: fit `composition ~ covariates` (no genotype) with a
   Dirichlet-Multinomial GLM, giving a per-individual linear predictor
   and a precision parameter (dispersion). Production runs should use
   the DRIMSeq-backed path (`use_drimseq="auto"`/`"yes"`), which fits
   *all* genes in a batch (or chunk) jointly so DRIMSeq's empirical-Bayes
   precision moderation has other genes to borrow strength from — a
   pure Python MLE fallback (`use_drimseq="no"`) is also included for
   environments without R, at the cost of gene-by-gene independent
   precision estimates.
2. **Score test scan**: for every cis-SNP of that gene, compute a
   Dirichlet-Multinomial score-test statistic (with a Schur-complement
   adjustment for the null-model nuisance parameters), fully vectorized
   across SNPs.
3. **Adaptive permutation + Beta approximation**: GTEx/FastQTL-style
   adaptive early-stopping permutation (minimum 1000, maximum 10,000
   permutations, early stop once ≥15 permuted min-p values beat the
   observed one) followed by a Beta-distribution approximation for the
   gene-level p-value.
4. **Storey q-value** across all gene×group units tested.

Outputs (`<prefix>.egenes.txt`, `<prefix>.cis_qtl_pairs.txt`,
`<prefix>.significant_pairs.txt`) follow the GTEx/tensorQTL convention.

## Installation

```bash
pip install -e .
```

Requires Python ≥3.9, `numpy`, and `scipy` (installed automatically).

### DRIMSeq (recommended for production use)

The null-model fitting step calls out to R/Bioconductor's `DRIMSeq`
package via `Rscript`. This is **optional but strongly recommended**:
without it, `dmqtl` falls back to an independent per-gene MLE that does
not borrow statistical strength across genes. See
[`INSTALL_R.md`](INSTALL_R.md) for conda/apt/Docker install instructions.

**Before running on real data**, run the R-bridge verification suite on
your own machine (this cannot be verified in CI — see
[`docs/DEVELOPMENT_NOTES.md`](docs/DEVELOPMENT_NOTES.md) for why):

```bash
python3 tests/test_r_bridge_smoke.py
```

## Quickstart

### Python API

```python
from dmqtl import run_dmqtl

summary = run_dmqtl(
    genotype_path="genotype.txt",
    phenotype_path="pas_counts.txt",
    pas_gene_map_path="pas_to_gene.txt",
    covariates_path="covariates.txt",
    snp_pos_path="snp_pos.txt",
    gene_pos_path="gene_pos.txt",
    output_prefix="out/apaqtl",
    use_drimseq="auto",
    n_workers=4,
)
print(summary)
```

### Command line

```bash
dmqtl-run \
    --genotype genotype.txt \
    --phenotype pas_counts.txt \
    --pas-gene-map pas_to_gene.txt \
    --covariates covariates.txt \
    --snp-pos snp_pos.txt \
    --gene-pos gene_pos.txt \
    --output-prefix out/apaqtl \
    --use-drimseq auto \
    --n-workers 4
```

Run `dmqtl-run --help` for the full option list (permutation settings,
DRIMSeq batching/chunking, MAF threshold, cis-window size, etc.).

## Input file formats

| File | Format |
|---|---|
| `--genotype` | variants × individuals, dosage-coded 0–2, tab/space-delimited, header = sample IDs |
| `--phenotype` | PAS/features × individuals, raw counts |
| `--pas-gene-map` | two columns: `pas_id`, `gene_id` |
| `--covariates` | individuals × covariates (no intercept column — added automatically) |
| `--snp-pos` (optional) | `variant_id, chr, pos` |
| `--gene-pos` (optional) | `gene_id, chr, start, end[, strand]` |

See `examples/` for a small synthetic dataset with all of these files
populated, generated by `examples/generate_synthetic_input.py`.

## Reproducing the validation in the manuscript

```bash
cd examples
python3 generate_synthetic_input.py   # regenerate the synthetic dataset
python3 run_synthetic_example.py      # run dmqtl end-to-end on it
```

This synthetic dataset embeds a known causal cis-SNP for 6 of 12 genes
and pure noise for the other 6; the expected result is that all 6
causal genes are recovered as eGenes with the correct lead variant, and
the null genes are (mostly — see the multiple-testing note below) not
significant. `tests/test_score_math.py` additionally validates the
core score-test statistic against brute-force numerical differentiation
and a likelihood-ratio-test alternative.

## Performance notes for large-scale runs

If you are scaling this up to a real cohort (many thousands of genes,
thousands of cis-SNPs per gene), two things matter a lot and are easy
to get wrong:

1. **Pin BLAS threads to 1 before importing numpy when using
   `n_workers > 1`.** `dmqtl-run`/`dmqtl.cli` does this automatically;
   if you call `run_dmqtl` directly from your own script, set
   `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1`
   **before** the first `import numpy`. Without this, the process-level
   parallelism (`multiprocessing.Pool`) and BLAS's own internal thread
   pool fight over cores — this was measured to cause a >30× slowdown
   in practice, not a minor inefficiency.
2. **Batch (or chunk) the DRIMSeq null-model fit across genes**
   (`null_fit_chunk_size`) rather than fitting one gene per R
   subprocess call — both for the R startup overhead and for DRIMSeq's
   cross-gene precision moderation to actually have other genes to
   borrow from. Two automatic safety checks flag genes whose
   `genewise_precision` estimate is likely a grid-search or
   distributional artifact (`converged=False` in the returned
   `NullFit`) rather than trusting them silently — see
   `nullmodel.fit_null_drimseq_batch`.

3. **Convert the genotype matrix once** with
   `dmqtl-convert-genotype genotype.txt geno` and pass the printed prefix
   to `dmqtl-run --genotype`. Genes then read only their cis columns on
   demand; for 9.2 M variants × 436 individuals this keeps task building
   under 10 GB, where the text reader needs well over 100 GB.
4. Permutations use the fast engine by default (`--perm-engine fast`,
   same results as `loop`, the v1.0.0 path); several DRIMSeq chunks can
   run at once with `--null-fit-parallel-chunks`. See
   [`CHANGES.md`](CHANGES.md) for what changed since v1.0.0 and how to
   reproduce it.
5. `--min-mac N` (default 0 = off) tests a SNP for a gene only if its minor
   allele is carried at least N times among the individuals with reads for
   that gene. Rare SNPs carried by one or two individuals with reads make the
   Beta approximation unreliable (the run warns about such genes); the full
   Ast run used N = 10.

Before committing to a full-cohort run, benchmark on a small gene
subset with the real per-gene SNP count and sample size to get an
accurate per-gene throughput estimate — see
[`docs/DEVELOPMENT_NOTES.md`](docs/DEVELOPMENT_NOTES.md) for the full
reasoning and the numbers this was validated against.

## Known limitations

See [`docs/DEVELOPMENT_NOTES.md`](docs/DEVELOPMENT_NOTES.md) for a
concise list, and [`CHANGES.md`](CHANGES.md) for the full development/
debugging log (kept intentionally detailed for reproducibility and
because several of the issues found — DRIMSeq's silent grid-boundary
saturation, its `prec_moderation`/`prec_prior_df` defaults, BLAS thread
oversubscription with multiprocessing — are generically useful to
anyone else calling DRIMSeq from a batched Python pipeline, not just
specific to this codebase).

## Repository layout

```
dmqtl/                  package source
  eqtl.py                  top-level run_dmqtl() orchestration
  io.py                    input file parsing / individual matching
  cis.py                   cis-window candidate SNP selection, MAF filtering
  nullmodel.py             null-model fitting (DRIMSeq bridge + python fallback)
  r_null_fit_batch.R        batched DRIMSeq null-fit R script
  dmglm.py                 Dirichlet-Multinomial GLM core math
  scoretest.py             vectorized score test + permutation
  pvalue.py                adaptive permutation, Beta approximation, Storey q-value
  pipeline.py              per-gene orchestration, batched null-fit + parallel scan
  cli.py                   `dmqtl-run` command-line entry point
tests/                   unit tests (see docs/DEVELOPMENT_NOTES.md for what needs R)
examples/                synthetic dataset + example scripts
docs/                    known issues / usage limits summary
```
